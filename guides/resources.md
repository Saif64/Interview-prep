# Resources Worth Your Time

A short, opinionated list. Everything here is genuinely good; nothing is here to pad the page.

---

## Practice platforms

| | What it's best for |
| :--- | :--- |
| [LeetCode](https://leetcode.com) | The default. Company tags and the "Top Interview 150" list are the useful parts. |
| [NeetCode](https://neetcode.io/practice) | The 150 in this repo, plus a video walkthrough for every one. Start here if you are unsure where to start. |
| [Codeforces](https://codeforces.com) | Genuinely hard, competitive. Overkill for most interviews, excellent if you enjoy it. |
| [HackerRank](https://hackerrank.com) | Where many online assessments actually run — worth doing a few for the interface alone. |
| [Exercism](https://exercism.org) | Language fluency with human mentorship, rather than interview problems. Good for picking up Kotlin properly. |

## Mock interviews

| | |
| :--- | :--- |
| [Pramp](https://www.pramp.com) | Free peer mocks. You interview someone, they interview you. |
| [interviewing.io](https://interviewing.io) | Anonymous mocks with engineers from large companies. Some free. |
| [Exponent](https://www.tryexponent.com) | Paid, structured, strong for system design and PM-adjacent roles. |

See [mock-interviews.md](mock-interviews.md) for how to actually use these.

## Books

- **Designing Data-Intensive Applications** — Martin Kleppmann. The one system design book
  worth reading cover to cover.
- **Cracking the Coding Interview** — McDowell. Dated in places, still the best single
  explanation of the *process*.
- **The Algorithm Design Manual** — Skiena. For when you want to understand algorithms rather
  than memorise them. The "war stories" are the best part.
- **Kotlin Coroutines: Deep Dive** — Marcin Moskała. If you are interviewing for Android, this
  covers the most-asked topic properly.
- **Never Split the Difference** — Voss. Negotiation. Yes, really.

## Courses and long-form

- [Grokking the Coding Interview](https://www.educative.io) — the pattern-based approach this
  repo's [patterns.md](patterns.md) is in the same spirit as. Paid.
- [MIT 6.006 Introduction to Algorithms](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/) — free, rigorous.
- [System Design Primer](https://github.com/donnemartin/system-design-primer) — free, broad,
  the standard starting point.

## YouTube

- [NeetCode](https://www.youtube.com/@NeetCode) — a walkthrough for every problem in
  `neetcode-150/`. The clearest explanations in the space.
- [Abdul Bari](https://www.youtube.com/playlist?list=PLDN4rrl48XKpZkf03iYFl-O29szjTrs_O) —
  algorithms, from first principles. Still unmatched.
- [ByteByteGo](https://www.youtube.com/@ByteByteGo) — system design, short and visual.
- [Philipp Lackner](https://www.youtube.com/@PhilippLackner) — modern Android and Kotlin.
- [Kunal Kushwaha](https://www.youtube.com/playlist?list=PL9gnSGHSqcnr_DxHsP7AW9ftq0AtAyYqJ) —
  long-form DSA in Java, from the beginning.

## Compensation data

- [levels.fyi](https://www.levels.fyi) — the most reliable for tech compensation by level.
- [Glassdoor](https://www.glassdoor.com) — broader, noisier.
- Your own network. Still the best source, and people are more willing to share than you
  expect.

See [negotiation.md](negotiation.md) for what to do with the numbers.

## Other repositories worth knowing

- [tech-interview-handbook](https://github.com/yangshun/tech-interview-handbook) — resume,
  behavioural, and the Grind 75 list.
- [coding-interview-university](https://github.com/jwasham/coding-interview-university) — a
  full multi-month CS curriculum. Thorough to the point of intimidating.
- [system-design-primer](https://github.com/donnemartin/system-design-primer) — as above.
- [TheAlgorithms](https://github.com/TheAlgorithms) — reference implementations in most
  languages.

## Staying current

Interview formats are shifting faster than they used to — see
[ai-era-interviews.md](ai-era-interviews.md). Worth watching:

- Company engineering blogs for the places you are targeting
- [Hacker News](https://news.ycombinator.com) hiring and interview threads
- r/cscareerquestions and r/ExperiencedDevs for what is actually happening in loops right now

Treat individual anecdotes as anecdotes. Patterns across many reports are the signal.
